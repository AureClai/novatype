Validation de schemas

NovaType utilise JSON Schema pour valider les metadonnees de vos documents, garantissant la coherence et la conformite.

Frontmatter YAML

Les metadonnees sont definies en YAML au debut du document, entre --- :

---
title: "Mon Article Scientifique"
authors:
  - name: "Jean Dupont"
    affiliation: "Universite de Paris"
    email: "jean.dupont@univ-paris.fr"
abstract: |
  Cet article presente une nouvelle approche pour...
keywords:
  - machine learning
  - data science
date: 2024-01-15
template: ieee-article
bibliography: "references.bib"
citation_style: "ieee"
---

// Contenu du document...
= Introduction

...

Commande de validation

# Valider un document
$ nova validate main.typ
✓ Document valid

# Validation stricte (frontmatter requis)
$ nova validate main.typ --strict

# Valider plusieurs fichiers
$ nova validate *.typ

# Utiliser un schema personnalise
$ nova validate main.typ --schema custom-schema.json

Schema par defaut

Le schema par defaut pour les articles :

{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "type": "object",
  "required": ["title"],
  "properties": {
    "title": {
      "type": "string",
      "minLength": 1,
      "description": "Titre du document"
    },
    "authors": {
      "type": "array",
      "items": {
        "type": "object",
        "required": ["name"],
        "properties": {
          "name": { "type": "string" },
          "affiliation": { "type": "string" },
          "email": { "type": "string", "format": "email" }
        }
      }
    },
    "date": {
      "type": "string",
      "format": "date"
    },
    "abstract": { "type": "string" },
    "keywords": {
      "type": "array",
      "items": { "type": "string" }
    },
    "template": { "type": "string" },
    "bibliography": { "type": "string" },
    "citation_style": {
      "type": "string",
      "enum": ["apa", "ieee", "chicago", "harvard", "nature", "vancouver"]
    },
    "language": { "type": "string" }
  }
}

Champs disponibles

Champ Type Requis Description
titlestringOuiTitre du document
authorsarrayNonListe des auteurs
datedateNonDate de publication
abstractstringNonResume du document
keywordsarrayNonMots-cles
templatestringNonTemplate a utiliser
bibliographystringNonChemin vers le fichier .bib
citation_stylestringNonStyle de citation
languagestringNonLangue du document

Schema personnalise

Creez votre propre schema pour des besoins specifiques :

// schemas/rapport.json
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "type": "object",
  "required": ["title", "author", "organization", "version"],
  "properties": {
    "title": { "type": "string" },
    "author": { "type": "string" },
    "organization": { "type": "string" },
    "version": {
      "type": "string",
      "pattern": "^\\d+\\.\\d+(\\.\\d+)?$"
    },
    "status": {
      "type": "string",
      "enum": ["draft", "review", "final"]
    },
    "confidentiality": {
      "type": "string",
      "enum": ["public", "internal", "confidential"]
    }
  }
}

Erreurs de validation

$ nova validate main.typ
✗ Validation failed:
  - Missing required field: title
  - Invalid email format in authors[0].email
  - Unknown citation_style: "mla" (expected: apa, ieee, chicago...)

Integration CI/CD

# .github/workflows/validate.yml
name: Validate Documents

on: [push, pull_request]

jobs:
  validate:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Install NovaType
        run: cargo install nova-cli

      - name: Validate documents
        run: nova validate **/*.typ --strict
Bonne pratique

Integrez la validation dans votre pipeline CI/CD pour garantir que tous les documents respectent le schema avant publication.
